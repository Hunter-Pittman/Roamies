# Agent Plugins conformance evidence

Target: [Agent Plugins 1.0.0](https://agent-plugins.org/specification), including its linked [Agent Skills specification](https://agentskills.io/specification). This document records implemented behavior and local Windows evidence. Optional and platform limitations are listed explicitly; it does not claim every MCP protocol extension or every operating system has been exercised.

The portable contract defines packages, skills and MCP configuration. Installation/trust UX, credentials, permissions, process sandboxing, extension behavior and delivery to independent agents are client features. Their tests are tracked separately so client policy is not confused with portable requirements.

## Completion record

Local evidence recorded on 2026-11-15. Source paths and tests above are relative to `showcase/tauri/sidecar`. Plan review, implementation, regression/build/package checks and Astra follow-up approval are complete. Windows app startup was verified after the final rebuild (`plugins_ready`, no unavailable plugins). No commit or push was requested for this goal.

Skill names follow the linked Agent Skills text's lowercase Unicode letter/number wording, normalized to NFC, with single hyphen separators; Greek is covered in the parser fixture. The 500-line recommendation is not a validity limit. YAML duplicate keys and aliases are rejected as client parser policy. Arbitrary supporting-resource folder names work.

The client pins MCP SDK 1.32.2, YAML 2.9.1 and Ajv 8.20.0. Pinned canonical schemas and their provenance ship in `plugin-schemas/`; loading never fetches schema URLs. Client limits: 2 MiB configuration/instruction files, 10,000 package entries, 128 MiB package bytes, depth 32, 24,000-character approval descriptor, 8 MiB MCP messages/results, 50 catalog pages/1,000 items, bounded request timeouts. Remote JSON Schema references are not fetched. Unsupported schemas fail clearly before a tool invocation.

Supported MCP operations are discovery, tool calls, resource reads and prompt retrieval. Roots, sampling, elicitation, subscriptions, task extensions, OAuth onboarding and legacy SSE are not advertised or claimed. Windows stdio requires a native executable; use `node` plus a script argument instead of a .cmd launcher. Package containment does not sandbox approved subprocesses. Owned-tree cleanup cannot undo remote effects or guarantee termination of detached descendants.


### Post-review corrections

- MCP schemas use [2020-12 by default](https://modelcontextprotocol.io/specification/2025-11-25/basic#schema-dialect). Explicit 2020-12 and draft-07 are recognized; unknown dialects fail clearly. Input and output validation runs independently against the selected tool metadata, captured from a complete catalog. Raw SDK protocol requests avoid its per-page mutable validation cache. Task-required tools fail before dispatch. `test/pluginschema.test.mjs` uses an actual local HTTP MCP fixture to cover valid/invalid tuples and dependent constraints, both output-schema page positions, missing/unsupported output, task-required tools on both pages, concurrent calls and catalog refresh.
- Approval descriptors are plain-text scrollable review bodies in the existing overlay confirmation, including while setup is open. Keyboard Page Up/Down, arrows, Home/End and wheel scrolling work; Allow/decline keep their real callbacks. `test/pluginapproval.test.mjs` exercises actual canvas rendering and verifies first/last command painting, scrolling, non-expiry and ordinary masked/text/choice prompts. Actual desktop HTML + host was opened in Orca's embedded browser: End reached the final HTTP endpoint; N delivered a null answer and Y delivered yes; a masked fixture prompt displayed dots. ## Subsequent Orca migration

The framework approval above predates the subsequent migration of Orca into the bundled `roamies.orca` package; it is not a claim that Astra reviewed that later migration. See [Orca plugin integration](orca-plugin.md) for its host-extension contract and verification. App-shipped packages use app trust and a managed, disabled-preference-preserving update path. Third-party packages retain the same disabled installation, explicit consent and isolation. Only app-owned instance/server bindings can use the narrow supervisor host service or the bundled runtime executable alias; package extension metadata cannot grant those privileges. Read-only Orca status retains its previous availability with actions off, while dispatch/messaging remain gated. The app retains saved state, report ingestion, notifications and the read-only overlay. The full 72-file sidecar suite passed after migration; targeted MCP/provider/recovery checks and relocated packaged-runtime checks cover the follow-up hardening.
